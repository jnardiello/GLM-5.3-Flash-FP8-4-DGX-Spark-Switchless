# September 28 accepted E31 reference: speculative-safe C4 tail ring

**Outcome: promote, accepted by the owner.** E31 keeps the E29 recipe. It replaces the
pooled indexer and its C4 kernels with copies that fix pools corrupted by speculative
decoding. The head-gate switch in the same files stays off.

- **The defect.** The indexer builds one pooled key from every four tokens. Each request
  keeps its recent key/gate rows in a tail so a pool can be completed across steps. That tail
  had four slots, indexed by `position % 4`. A DFlash2 verify step writes 1 + 7 consecutive
  positions, and later drafts in the step may be rejected. Their rows overwrote slots that
  still held committed members of the open pool, and after a rejection the next step
  completed that pool from rejected-draft keys. Example: positions 0 and 1 committed, one
  verify step over 2..9 that accepts only 2. The next step builds pool 0..3 from the keys of
  8, 9, 6 and the new 3. The target verify has no rollback; only the MTP speculator snapshots
  the tail.
- **The fix (`VLLM_GLM53_KPOOL_TAIL_RING`, on by default).** The tail becomes a ring of
  `4 * cdiv(4 + K, 4)` slots, 12 for seven drafts, indexed by `position % ring`. The pool
  phase stays `position % 4`. A verify step spans at most K + 1 positions, so none of its
  rows can reach a committed member of the open pool. With a ring of 4 every index equals
  the legacy one.
- **Head gate (`VLLM_GLM53_INDEXER_GATE_TC`, off).** The indexer head gate can run as a BF16
  tensor-core GEMM with FP32 output instead of an FP32 GEMM. Its same-load comparison is
  unresolved, so it stays off.

Both switches come from one [overlay](../../../scripts/node/experiments/e03/e31-indexer/README.md),
measured as [E31](../experiments/2026-09-28-e31-indexer.md). The default IaC now encodes it.
The [promotion record](../../historical_benchmarks/baselines/2026-09-28-e31/promotion.json)
records how it was applied.

## Measurement protocol

This is the first reference measured under the owner's current Rigmark policy:

- **Rigmark.** Upstream, unmodified Rigmark (`alexellis/rigmark` c5a0db0), with exactly the
  reference flags of Alex Ellis's GLM receipts: every default plus
  `--extra-body '{"chat_template_kwargs": {"reasoning_effort": "low"}}'`.
- **Cache isolation.** No cache salt. Each suite has a fresh comparison ID
  (`glm53-e31-alex-20260928-s1` to `-s3`), whose nonce starts every prompt.
- **Arms.** One load, three complete suites, one per arm, switched at runtime through the
  flag files. Before each suite the service was idle and all four ranks showed the intended
  flag values and log lines.

| Arm | Gate | Ring | Meaning |
| --- | --- | --- | --- |
| E | 0 | 0 | E29-equivalent arithmetic: legacy four-slot tail, FP32 head gate |
| **R** | **0** | **1** | **The promoted default: 12-slot ring, FP32 head gate** |
| G | 1 | 1 | Ring plus the tensor-core head gate |

The reference values are arm R's single suite (**n = 1**, 54 requests). Arm E, measured on
the same load with the same flags, is their comparison. Frozen records up to
[E29](2026-09-25-e29.md) used 8,192 decode tokens, thinking off and a local Rigmark fork
that forwarded a cache salt to prefill requests. They are historical and cannot be
compared with these values.

measurement, not a median. The C1/C2/C4 rows each rest on three short rounds and moved up to
about 7% in both directions between arms.

The ring's cost is not measurable at this depth: the code and prose decode rows move less
than 1%, and the concurrency rows move in both directions.

Arm G against R is inconclusive. Changing the gate's accumulation order changed some
generated tokens and therefore draft acceptance, which moves decode and concurrency by
more than the gate's own kernel time. The gate stays off and its outcome is **unresolved**.

## Correctness evidence

- **Offline proof.** [`test-e31-kpool-tail-ring.py`](../../../scripts/tests/test-e31-kpool-tail-ring.py)
  re-implements the three kernels' index arithmetic, checked verbatim against the source.
  It simulates chunked prefill and verify steps with random acceptance: the legacy tail
  corrupts pools, the ring never does.
- **GPU leaf test.** The [kpool leaf](../../historical_benchmarks/experiments/2026-09-28-e31-indexer/leaf-kpool-tail-ring.json)
  ran the real Triton kernels on one GB10 with the production page geometry: four requests
  in mixed decode/prefill batches, non-contiguous state slots. Each ring was compared with a
  prefill over the committed tokens only.
  - Legacy ring: 1 wrong pool in the reported counterexample and 200 in the random
    schedule, with a maximum difference of 3.06.
  - E31 ring: none, bit-exact.
- **Head-gate leaf test.** The [gate leaf](../../historical_benchmarks/experiments/2026-09-28-e31-indexer/leaf-gate-tc.json)
  used the real layer-11 gate weights. It changed no top-512 selection at 4 to 48 rows, with
  a maximum relative error of 8.4e-4.

## Integrity

Every suite completed **54/54 streams visibly** with DONE markers, with zero native,
protocol or runtime errors. Code, prose and structured gates pass **5/5** each. Prefill
token counts match **18/18**. The client path lost no probe during any suite. Both post-boot
gates passed 4 s after `/health` 200.

Two earlier series on this load were stopped by the owner before completing a suite and
are [excluded](../../historical_benchmarks/experiments/2026-09-28-e31-indexer/excluded-series.json):

- one ran with the template's default reasoning effort;
- one ran with the local fork and a cache salt.

## Costs, risks and limits

- **n = 1.** One suite per arm on one load. Differences of a few percent, and the concurrency
  rows' ±7%, are not distinguishable from noise.
- **SparkCache namespace kept.** By owner decision the E22b namespace was kept, with no
  restart. Decode-built pools written with the legacy tail could be restored for resumed
  sessions. It is not established that decode-built pools are persisted; the external
  review concurred that this is not a confirmed blocker.
- **Not measured.** Host memory was not sampled and the interference phase did not run.
- **Upstream status.** vLLM merged the equivalent fix for its own kpool compressor on
  September 25, 2026 (PR #58454). The SparkRing source of the R10 image still has the
  four-slot tail. Its MTP3 profiles snapshot and restore the tail, so the defect affects
  DFlash2.

## Reproduction identity

- **Base recipe.** Everything in the [E29 reference](2026-09-25-e29.md#reproduction-identity).
- **Mounts.** `experiments/e03/e31-indexer/pooled_indexer.py` and `glm_kpool.py` replace the
  production `pooled_indexer.py` and `ops/glm_kpool.py` mounts.
- **Environment.**
  `VLLM_GLM53_INDEXER_GATE_TC_FLAG=/tmp/glm53-indexer-gate-tc` and
  `VLLM_GLM53_KPOOL_TAIL_RING_FLAG=/tmp/glm53-kpool-tail-ring`, with both switches unset
  (gate 0, ring 1).
- **Startup.** Every rank logs `E31_INDEXER_GATE path=fp32` and
  `E31_KPOOL_TAIL_RING ring=12` on its first forward. `scripts/check-f0.py` checks both
  files, both variables, the absence of the switch variables and both lines.

Rollback to E29 is one complete overlay: `TP4_ENV=scripts/node/reference/baseline-20260925-e29.env`.
