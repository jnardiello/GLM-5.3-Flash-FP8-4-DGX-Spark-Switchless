# September 30 E31-MB reference: E31 engine with the memory-bounded layer

**Status: previous performance reference, named by the owner; superseded by [E35](2026-09-30-e35.md).** E31-MB was the operational
default measured as it serves: the unchanged [E31 engine](2026-09-28-e31.md) plus the
memory-bounded layer and the protected SparkCache connector.

| Layer | Setting |
| --- | --- |
| KV pool | 14 GiB per rank (1,194,033 tokens, 4.55 maximum-length contexts) |
| Allocator trim | before every eager prefill step over 72 tokens |
| Step cap | 6,912 tokens per scheduling step |
| API admission | six active, 128 queued |
| SparkCache | protected RAM-budget connector; disk capacity 200 GiB, trimmed to 160 GiB per rank |

Its runtime identity is
[`2026-09-30-e31-mb`](../../operational-identities/2026-09-30-e31-mb.json), frozen with this
record. Since E35, the
[`2026-09-30-e31-mb-return`](../../operational-identities/2026-09-30-e31-mb-return.json)
identity checks the same runtime reached from the E35 template. The frozen E31 record is unchanged; its engine
hashes remain the engine identity.

## Measurement

- **Suites.** Two complete native Rigmark suites of the default arm, A1 and A4 of the
  [E32 A–P–P–A series](../experiments/2026-09-30-e32-prefill-switches.md), on one load
  (n = 2, 108 requests).
- **Protocol.** Upstream Rigmark `c5a0db0` with the reference flags (every default plus
  `reasoning_effort` low), no cache salt, fresh comparison IDs
  `glm53-e32-suite-20260930-r2-s1` and `-s4`, direct LAN HTTP to the rank-0 API.
- **Runtime.** The suites ran on the E32 overlay with its flag files at the default's
  behaviour: trim `1`, cap `6912`, head gate off. Its worker and scheduler differ from the
  default's sources only by the flag-file readers; the overlay was discarded afterwards.
- **Integrity.** 108/108 requests completed with visible responses, 36/36 exact prefill
  token counts, 30/30 decode output gates, zero validation, protocol or runtime errors. A
  memory guard streamed MemAvailable from every rank; rank 0 never fell below 5.05 GiB.

No difference against E31 exceeds the variation between loads: single-request metrics vary
by a few percent and concurrency by up to about 10%. None of these differences is therefore
attributed to the operational layer.

## Limits

- Two suites of one arm on one load; C1/C2/C4 differences within about 7% are noise.
- The disk-capacity policy was added after the measurement. It acts only when a rank's
  store exceeds 200 GiB; the stores held 78–85 GiB at the next boot.
- Before this series the load had served the overnight screen and a resilience stress, and
  its cache store had been cleaned in place after the disks filled.
