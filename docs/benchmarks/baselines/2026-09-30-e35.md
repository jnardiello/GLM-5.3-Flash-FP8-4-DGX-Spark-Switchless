# September 30 E35 reference: E31-MB with the E35 verify length

**Status: previous performance reference, promoted by the owner; superseded by [E36](2026-09-30-e36.md).** E35 is the operational
default measured as it serves. It is [E31-MB](2026-09-30-e31-mb.md) plus the E35 verify
length. On a single-request decode step with seven scheduled drafts, the model runner
verifies 3 or 7 drafts, chosen from the DFlash2 selector's own confidence under the `hybrid`
policy. Rank 0 decides and broadcasts the choice to every tensor-parallel rank.

Its runtime identity is
[`2026-09-30-e35-hybrid`](../../operational-identities/2026-09-30-e35-hybrid.json),
frozen with this record; since E36 the `2026-09-30-e35-return` identity checks the same runtime
reached from the E36 template. The frozen E31 record remains the engine identity.

## Measurement

- **Suites.** Two complete native Rigmark suites of the `hybrid` arm, P2 and P3 of the
  [E35 A–P–P–A series](../experiments/2026-09-30-e35-runner-k.md), on one load (n = 2, 108
  requests). The same-load `ema` suites A1 and A4 are kept per metric as the comparison.
- **Protocol.** Upstream Rigmark `c5a0db0` with the reference flags (every default plus
  `reasoning_effort` low), no cache salt, a fresh comparison ID per suite, direct LAN HTTP to
  the rank-0 API.
- **Runtime.** The suites ran the measured overlay, with `hybrid` written into the rank-0
  container's policy file at runtime. The default mounts an equivalent read-only file; only
  that file's bytes differ (a trailing newline), and the reader ignores them.
- **Integrity.** 108/108 requests completed with visible responses, 36/36 exact prefill token
  counts, 30/30 decode output gates, zero validation, protocol, runtime or E35 decision
  errors. The memory guard never triggered; rank 0 never fell below 4.76 GiB.

## Values

Median of the two `hybrid` suites (their mean), against the mean of the same-load `ema`
suites and the drift between them.

| Metric | E35 | Same-load `ema` | Change | `ema` drift |
| --- | ---: | ---: | ---: | ---: |
| Code decode | 64.1 tok/s | 64.0 tok/s | +0.1% | +0.9% |
| Prose decode | 33.4 tok/s | 33.9 tok/s | −1.5% | +0.5% |
| Code decode TTFT | 0.457 s | 0.488 s | −6.4% | −0.2% |
| C1 aggregate | 45.9 tok/s | 45.1 tok/s | +1.8% | +1.9% |
| C2 aggregate | 73.8 tok/s | 73.0 tok/s | +1.1% | +7.1% |
| C4 aggregate | 107.3 tok/s | 108.4 tok/s | −1.0% | +0.4% |
| Prefill cold 8K / 32K / 64K | 2,621 / 2,764 / 2,782 tok/s | 2,634 / 2,763 / 2,782 tok/s | −0.5 / 0.0 / 0.0% | 0.0 / +0.7 / +0.4% |
| Replay 8K / 32K / 64K | 8,809 / 35,970 / 40,338 tok/s | 8,944 / 35,646 / 39,562 tok/s | −1.5 / +0.9 / +2.0% | −2.4 / −2.9 / +0.1% |

Code decode and C1 moved less than the drift of the `ema` arm. The owner judged the prose
change to be noise, and the lower decode time to first token to be real: both `hybrid`
suites show it. Steps with several requests do not use E35, so the C2 and C4 differences
are noise.

## Limits

- Two suites of one arm on one load; C1/C2/C4 differences within about 7% are noise.
- The E35 calibration came from thinking-off captures; with reasoning effort low, `hybrid`
  verified 3 drafts on about two thirds of its steps.
- The comparison arm `ema` carried the overlay: rank 0 still broadcasts the unchanged length
  on its seven-draft steps.
