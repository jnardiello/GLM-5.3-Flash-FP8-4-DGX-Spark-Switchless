# E38: MLA preparation on four GB10 ranks

**Recorded outcome: unresolved; independent review gives NO-GO to prototype.** The experiment examines
input normalization around Q-B on the complete [E36 operational reference](../baselines/2026-09-30-e36.md).
No candidate kernel or candidate performance result is included. E36 is restored and
healthy on all four ranks; the frozen reference and operational recipe are unchanged.

The retained four-rank observations put the optimistic preparation budget at about
**48–52 µs per target step** for the main C1/C2/C4 shapes, against target graph spans
of about **52–101 ms**. This includes both query and KV normalization and intervening
gaps, assumes zero fusion overhead, and excludes Q-B matrix multiplication. The estimate
cannot establish an improvement in generation throughput. Numerous shape-dependent
timestamp exclusions further limit its interpretation.

The hardware is four GB10 GPUs, one per tensor-parallel rank, on the switchless ring.

## MLA census and attribution

Each rank has eleven MLA layers, at indices 3, 7, 11, 15, 19, 23, 27, 31, 35, 39 and 43.
Installed wrapper, attention and linear hashes match the tracked E03 sources on all
four ranks. The seven inspected Python source hashes agree across ranks; the portable
extract records them. Model configuration and source inspection give this contract:

| Property | E36 MLA preparation |
| --- | --- |
| QKV-A / Q-B weight shapes, N × K | 2,048 × 4,096 / 4,096 × 1,536 |
| Query / KV low-rank widths | 1,536 / 512 |
| Heads per rank / width | 16 / 256 |
| Observed graph rows | 4, 8, 16; graph padding rows are not concurrent request counts |
| Packing | Marlin `uint8b128` INT8, group 128, int32 packed weights and BF16 scales |
| Projection padding | N aligned to 256, K unpadded; no additional N/K padding at these shapes |
| Arithmetic | FP32 Marlin reduction, BF16 projection and normalization outputs, RMS epsilon 1e-5 |
| Split input views | 2,048-element row stride; query and KV initially share QKV-A storage |
| Query materialization | Normalized BF16 `q_c` is still consumed by the sparse indexer |
| MLA RoPE width | Zero: no Q/K-RoPE arithmetic is available to remove |

Normalization materializes separate query and KV outputs; Q-B output is viewed as
16 heads. These alias and rounding descriptions are **source-derived**, not a completed
runtime pointer/write-region or adversarial numerical qualification. No shape has been
qualified for a prototype. Native QKV-A, the indexer, attention and KV updates remain
outside the proposed fusion. Prefill, mixed requests and unqualified shapes would use E36.

Exact installed Marlin C++ provenance remains unresolved: no source was located in the
inspected image build locations. No upstream approximation or replacement toolchain was
used. There is no eager/CUDA-graph candidate bit-identity result.

A target graph is identified by 84 `fused_moe_kernel` launches sharing one process,
device, context and correlation. Each of its eleven preparations has consecutive graph
nodes on one stream: Marlin QKV-A, query RMSNorm, KV RMSNorm, Marlin Q-B.
The Marlin grid/block is `(48,1,1)/(256,1,1)`; query and KV norm blocks are
`(192,1,1)` and `(64,1,1)`, with grid `(m,1,1)`. Other Marlin and normalization
kernels are excluded from this attribution.

## Four-rank bound and exclusions

There are **1,705 full target graphs per rank**, each structurally mapping all eleven
preparations. Strict timestamp and phase guards retain 1,206 / 1,463 / 1,438 / 1,303
graphs by rank. The remaining counts are respectively 381 / 107 / 128 / 287 with
nonmonotonic kernel timestamps and 118 / 135 / 139 / 115 near phase boundaries.

Graphs are matched by their complete chronological sequence across the synchronized
ranks. All 1,705 ordinals agree in shape and native phase; aligned start skew has
p50 8.942 ms and maximum 9.132 ms, within probe uncertainty. A joint observation is
retained only when all four rank records pass. This retains **870/1,705 graphs** and
excludes **835**. Joint reason counters can overlap; each excluded graph counts once
in the total. Four ranks are not four independent repetitions.

For each retained step, the optimistic bound sums eleven **per-layer maxima across
ranks** of the interval from QKV-A end to Q-B start. This allows the slowest rank to
change between layers and includes both normalizations and gaps. Q-B duration is
diagnostic and contributes no removable time. The denominator is the maximum rank
target graph span; a complete service step also includes work outside that graph.
Actual fusion still has to materialize `q_c`, preserve BF16 rounding and execute Q-B.

Fraction percentiles are computed per step, not from ratios of independently aggregated
percentiles. p50 is the median; p99 uses the nearest observed index
`round((n−1)×0.99)`. Preliminary prose/structured and sparse concurrency drain cells
are separate in the extract. C2/4 rows and C4/4 or 8 rows retain only 1–3 graphs;
their empirical p99 cannot support a tail inference.

There is **one profiled execution**. No paired candidate confidence interval or repeated
service benefit is available. CUPTI timestamp overlaps are conservatively excluded;
the exclusions depend on shape, so these are retained-subset estimates rather than
universal bounds. Pre/post SSH clock probes and a one-second empirical phase guard
help separate native phases, but logger delay and clock drift between probes remain
unbounded. Profiling perturbs execution. The warmup/profile throughput differences
also include different request nonces and between-execution variation, and cannot be
interpreted as a candidate regression or a controlled profiler-overhead measurement.

## Decision, restoration and evidence

Independent fresh-context review reproduced all four SQLite analyses and
the joint result exactly, reconciled native counts/hashes/metrics and verified the
public tables. Both extract-integrity findings were fixed; no findings remain outstanding.
The prototype GO is withheld because realizable removable critical-path margin is
not established and exact installed Marlin C++ provenance is unresolved. This decision
uses no fixed percentage floor and claims neither measured speedup nor regression.
No candidate was measured, so this is not a regression-based discard.

The experiment stops at diagnostics. **Prototype, eager/CUDA-graph bit-identity
qualification, three paired full-chain microbenchmark blocks, integration and all
seven planned A×3/P×3/A×1 full service suites are skipped.** None of the planned
378 service requests were sent. There is no numerical candidate PASS, chain speedup,
paired 95% interval, promotion or replacement baseline.

The complete E36 default is restored through coordinated four-rank shutdown using
the profiler overlay, followed by default deploy, fabric verification and startup
without the overlay. `/health` returns 200; both functional gates pass within
**3.7 seconds** of the first observed health 200. The operational identity check passes
on all four ranks. Autostart unit hash is unchanged, and all **33** checked frozen
reference/configuration files retain their original hashes. The profiled boot had also
passed both gates within 34.9 seconds. These four documented gate requests are separate
from the 48 native diagnostic requests.
