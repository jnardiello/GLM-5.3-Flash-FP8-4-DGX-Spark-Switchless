# E28: seven draft tokens for a single request

**Recorded outcome: superseded.** The owner accepted E28 and then asked for a 16 GiB KV pool;
[E28b](2026-09-25-e28b-kv16.md), which adds only that, was promoted as the
[September 25 E28b reference](../baselines/2026-09-25-e28b.md).

## Why

An audit of the DFlash2 drafter found that the serving image runs it as designed: 16
candidates per position and the candidate selector. The drafter is trained with blocks of
eight positions, while the recipe let a single request draft only five tokens. At five,
code still accepted the fifth position in 39–58% of steps. Prose without thinking stays at
three tokens, because the adaptive policy drops there. A reopened E10 question: fixed
depth seven had been closed on an older drafter and adaptive policy.

## Change

The [overlay](../../../scripts/node/experiments/e03/draft-depth-7/README.md) sets
`SPEC_TOKENS=7`, the table `[[1,1,7],[2,6,3]]`, `VLLM_ADAPTIVE_K_HI=7` and
`--compilation-config={"max_cudagraph_capture_size":72}`, so that the captured CUDA graph set
stays that of E27c. Rank 0 had little free memory, and without the limit vLLM would capture
more graphs.

## Measurement

One coordinated transition from E27c, then on one retained load: acceptance probes without
and with thinking and **three complete native suites**. Integrity: 162/162 requests with
zero errors, gates 45/45, no lost client probe.
