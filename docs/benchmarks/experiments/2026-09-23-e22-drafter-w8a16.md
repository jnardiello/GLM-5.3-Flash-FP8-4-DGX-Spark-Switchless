# E22: 8-bit weights for the DFlash2 drafter, context K/V included

**Recorded outcome: superseded by [E22b](2026-09-23-e22b-drafter-context-bf16.md).**
E22 converted 31 BF16 linears of the DFlash2 speculative drafter to the accepted E20/E21
INT8 group-128 format, including the drafter's fused context K/V projection. Three
complete native Rigmark suites, 162 requests, on one retained load; one supplementary
suite and diagnostic probes were kept separate.

## Why this candidate

After E21 the drafter was the largest remaining BF16 block: 4.81% of summed kernel time in
the single-stream decode profile. The drafter only proposes tokens and the target model
verifies them, so its precision is expected to change acceptance rather than answers. A
byte-traffic model gave roughly +1.4% to +2.5% single-stream.

## Result against E21

| Metric | E21 | E22 | Change |
| --- | ---: | ---: | ---: |
| Code decode | 54.945 tok/s | 56.504 tok/s | +2.84% |
| Code C1 | 40.718 tok/s | 41.694 tok/s | +2.40% |
| Code C2 | 64.726 tok/s | 67.240 tok/s | +3.88% |
| Code C4 | 95.524 tok/s | 94.690 tok/s | -0.87% |
| Prose decode | 32.441 tok/s | 33.010 tok/s | +1.75% |
| C1 per-stream TTFT | 0.3500 s | 0.3910 s | +11.71% |
| Prefill 8K, cold | 2,644.825 tok/s | 2,548.698 tok/s | -3.63% |

All 162 requests completed with zero errors. An external review recommended `unresolved`:
code, C1 and prose gains were favourable but small, C4 did not gain, and two drawbacks
needed attribution.

## What the diagnosis found

Matched native probes on E22, on E21 after one transition and on E22b after a second
separated the two drawbacks:

- **C1 time to first token was not an E22 cost.** First-token times are quantized in
  engine-step units in every variant; over 30 identical C1 rounds E21 was no faster
  (median 0.404 s against 0.394 s).
- **The 8K cold prefill loss was real:** median 2,571.5 against 2,650.4 tok/s over 10
  identical pairs. The converted context K/V projection sits on the prefill path,
  dequantizing its weights for every large prefill chunk.

Keeping that one projection in BF16 is E22b. It recovered the prefill (2,639.5 tok/s) and
drafter acceptance (0.61–0.62 against 0.58–0.61 for E22) while keeping the throughput
gains.
