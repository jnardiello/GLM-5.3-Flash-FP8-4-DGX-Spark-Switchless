# E31: speculative-safe C4 tail ring, and the head gate on tensor cores

**Outcome:**
- **Tail ring:** promote, accepted by the owner. It is the
  [September 28 E31 reference](../baselines/2026-09-28-e31.md).
- **Head gate:** unresolved; it stays off.

## Candidate

One [overlay](../../../scripts/node/experiments/e03/e31-indexer/README.md) on the complete E29
recipe swaps the production `pooled_indexer.py` and `ops/glm_kpool.py` for copies with two
runtime switches. Each switch has an in-container flag file, so the variants can be compared
on one load without a restart:

- **`VLLM_GLM53_KPOOL_TAIL_RING`** (overlay default 1). The C4 key/gate tail becomes a ring of
  `4 * cdiv(4 + K, 4)` slots, 12 for seven drafts. With the legacy four slots, rows of
  rejected drafts overwrote committed members of the still-open pool.
- **`VLLM_GLM53_INDEXER_GATE_TC`** (default 0). The indexer head gate becomes a BF16
  tensor-core GEMM with FP32 output instead of an FP32 GEMM. The idea follows the Apache-2.0
  RiNGSiDE `GLM53_INDEXER_GATE_TC` patch.

The offline tests prove the ring's index arithmetic against the kernel source, check the
patches, the switches and four-rank launcher parity, and cover refused bases.

## Maintenance-window leaf tests

Both leaf tests ran on one GB10 inside the serving image with the stack down.

- **Tail ring** ([summary](../../historical_benchmarks/experiments/2026-09-28-e31-indexer/leaf-kpool-tail-ring.json)).
  The run used the production page geometry: 2304-token parent pages, 153-page parent stride,
  four requests with non-contiguous state slots, and 163 mixed decode/prefill batches. Pools
  were compared with a prefill over the committed tokens, and sampled pools with an
  independent Torch computation of the pool formula.
  - Legacy ring: 1 wrong pool on the reported counterexample and 200 on the random schedule,
    with a maximum difference of 3.06.
  - E31 ring: 0, bit-exact.
- **Head gate** ([summary](../../historical_benchmarks/experiments/2026-09-28-e31-indexer/leaf-gate-tc.json)).
  With the real layer-11 gate weights there were 0 top-512 mismatches at M = 4 to 48 and a
  maximum relative error of 8.4e-4. `torch.mm(..., out_dtype=float32)` was available. The
  gate took 14–20 µs instead of 20–26 µs eager, and 7–19 µs instead of 11–22 µs under CUDA-graph
  replay (medians of 200 iterations per row count).

## Serving measurement

One load of the overlay was booted on 2026-09-28. Both gates passed 4 s after health.
Three complete suites followed, one per arm, all with upstream Rigmark (`alexellis/rigmark`
c5a0db0) and the reference flags: defaults plus `reasoning_effort` low, no cache salt, and a
fresh comparison ID per suite. Before each suite the flags were switched with the service
idle, and all four ranks were verified through their flag files and log lines.

| Arm | Gate / ring | Suite |
| --- | --- | --- |
| E | 0 / 0 (E29-equivalent) | `glm53-e31-alex-20260928-s1` |
| R | 0 / 1 (promoted) | `glm53-e31-alex-20260928-s2` |
| G | 1 / 1 | `glm53-e31-alex-20260928-s3` |

The per-arm values are in the [reference report](../baselines/2026-09-28-e31.md#performance)
and in [results.json](../../historical_benchmarks/experiments/2026-09-28-e31-indexer/results.json).

- **R against E:** code decode +0.97%, prose -0.54%, code TTFT +0.42%, prefill within ±3.5%.
  C1/C2/C4 end-to-end moved +7.3%/-6.5%/-6.7%, each from three short rounds. That is noise,
  not a cost of the ring.
- **G against R:** inconclusive. Changing the gate changed generated tokens and therefore
  draft acceptance: code decode -4.1%, C2 +11.8%.

Every suite completed 54/54 requests with zero errors and 15/15 native output gates.
Values are single suites (n = 1).

## Decision

The [owner](../../historical_benchmarks/experiments/2026-09-28-e31-indexer/owner-decision.json)
promoted the ring, with the gate present and off, exactly as the overlay was measured:

- **No restart.** The running service already was the overlay.
- **SparkCache namespace kept.** The residual risk of restored legacy decode-built pools is
  recorded.
- **Upstream.** vLLM merged the equivalent fix on 2026-09-25 (PR #58454). The SparkRing
  source of the R10 image still has the four-slot tail.
