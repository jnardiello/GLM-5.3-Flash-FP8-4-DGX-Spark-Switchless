# E20: control and hybrid screens

**Recorded outcome:** diagnostic comparison; no disposition recorded.

Two separate 13-request screens (26 total); not the standing full-suite repetition protocol.

Each screen uses three short decode requests (256-token caps) and ten prefill requests across five context depths. Both completed 13/13 requests with no native integrity findings, 13 DONE/visible responses and 13 length finishes. The three decode output gates are 0/3 because of normal caps; this does not turn the measured streams into transport errors.

The control was already warm from previous full runs; the hybrid used a fresh boot. A JIT compilation was observed during the first hybrid 8K prefill. Its cost is not isolated, so the screen does not establish the cause of differences. No promote/discard verdict was recorded.
