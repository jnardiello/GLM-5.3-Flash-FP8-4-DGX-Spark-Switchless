# E35: verify length decided in the model runner from the drafter's confidence

**Recorded outcome: promote (owner decision).** The owner judged the prose change to be
noise and the lower decode time to first token to be real, and promoted the `hybrid` policy
to the default. A read-only policy file selects `hybrid` at boot, and the code keeps the
measured bytes. The owner had first discarded the experiment the same day and reversed that
decision after reviewing the results.

- One load, switched at runtime through a flag file. A held-out screen ran four arms of 25
  requests each, with thinking off. Four complete native Rigmark suites followed, A–P–P–A
  (216 requests), with the reference flags.
- Comparison reference: arm A on the same load. Arm A is the default's verify length with the
  overlay loaded. The previous frozen reference is the [E31-MB record](../baselines/2026-09-30-e31-mb.md).
  The two `hybrid` suites are frozen as the
  [E35 record](../../historical_benchmarks/baselines/2026-09-30-e35/baseline.json).

## Why

The default's adaptive verify length follows an exponential moving average of acceptance.
The scheduler fixes a step's draft count before the draft being verified exists. The
decision therefore uses acceptance data two steps old.

The DFlash2 drafter's candidate selector scores its own choices. The softmax probability
of each chosen draft token predicts whether the target accepts it. An offline replay put
that prediction at an ROC AUC of 0.91 and estimated a 3.8–5.7% gain on short code tasks.
The model runner prepares a step when the previous draft's scores are already on the GPU,
one step fresher than the scheduler.

## What the candidate changed

Additive wrappers around the V2 model runner's `execute_model()` and the DFlash2
speculator's `propose()`, plus the default scheduler with one addition.

- **Participation.** A step participates only when it holds one request with seven
  scheduled drafts. That condition comes from the scheduler output, which is identical on
  every rank.
- **Decision.** Tensor-parallel rank 0 chooses 3 or 7 drafts. It uses an isotonic calibration
  of the per-position confidence, fitted on thinking-off captures, and the measured step
  costs.
- **Consistency across ranks.** Rank 0 broadcasts the choice over the tensor-parallel CPU
  group, so the ranks cannot disagree.
- **Trim.** Every rank runs a trimmed copy of the scheduler output. Trimmed drafts count as
  rejected, so the scheduler's token accounting is unchanged.
- **Policy flag.** A flag file selects `ema` (no trim), `lag1` (the previous draft's
  confidence, no wait) or `hybrid`. `hybrid` waits for the current draft's confidence only
  when the rule's margin is small. Under `lag1` and `hybrid` the scheduler gives
  single-request steps seven drafts, and the runner chooses.

Every rank loaded the overlay, both functional gates passed, and no decision error or
collective failure occurred in about 30,000 participating steps.

## Held-out screen (thinking off)

The held-out set was frozen before the experiment: 10 short code tasks, each run twice at
256 tokens, plus 2 long code tasks and 3 prose tasks at 8,192 tokens. Each value is the
median over tasks of the per-task decode change against the mean of the two `ema` arms.

| Arm | Short code | Long code | Prose | Frozen gate |
| --- | ---: | ---: | ---: | --- |
| `lag1` | +1.96% (7/10 tasks faster) | +3.5% | +3.5% | fail (short below +2%) |
| `hybrid` | +5.1% (9/10) | +2.6% | +4.3% | pass |
| `ema` second vs first run | +0.4% (5/10) | +4.6% | +0.8% | noise reference |

`hybrid` waited on 19.5% of steps. The wait took 4.9 ms against the 2.8 ms assumed in the
replay, and the arm still passed.

## Native suites

The suites used the reference flags, with reasoning effort low. Arm A is `ema`; arm P is
`hybrid`. Each arm value is the mean of its two suites, and the A4-versus-A1 drift is the
noise reference.

| Metric | A | P | P vs A | A drift |
| --- | ---: | ---: | ---: | ---: |
| Code decode | 64.0 tok/s | 64.1 tok/s | +0.1% | +0.9% |
| Prose decode | 33.9 tok/s | 33.4 tok/s | −1.5% | +0.5% |
| Code decode TTFT | 0.488 s | 0.457 s | −6.4% | −0.2% |
| C1 aggregate | 45.1 tok/s | 45.9 tok/s | +1.8% | +1.9% |
| C2 aggregate | 73.0 tok/s | 73.8 tok/s | +1.1% | +7.1% |
| C4 aggregate | 108.4 tok/s | 107.3 tok/s | −1.0% | +0.4% |
| Cold TTFT 8K / 32K / 64K | 3.11 / 11.86 / 23.56 s | 3.13 / 11.86 / 23.56 s | +0.5 / 0.0 / 0.0% | 0.0 / −0.7 / −0.4% |
| Replay TTFT 8K / 32K / 64K | 0.916 / 0.919 / 1.657 s | 0.930 / 0.911 / 1.625 s | +1.5 / −0.9 / −1.9% | +2.4 / +3.0 / −0.1% |

- **No gain in the primary metrics.** Code decode and C1 moved less than the drift between
  the two A suites.
- **Prose is slightly slower.** Both P suites ran below both A suites.
- **C2 and C4 are noise.** Their steps hold several requests and do not participate.
- **Decode TTFT is about 30 ms lower.** Both P suites show it.
- **Draft length.** With reasoning effort low, `hybrid` verified 3 drafts on about two
  thirds of its steps and waited on about 12%. The thinking-off calibration did not carry
  its held-out decode gain to this workload.
- **Integrity.** 216/216 requests completed without errors, and 60/60 decode output gates
  passed with a normal stop. The memory guard (stop below 0.75 GiB) never triggered; the
  lowest rank-0 MemAvailable was 4.75 GiB.

## Measurement notes

- **Client and protocol.** Upstream Rigmark `c5a0db0` with the reference flags (defaults
  plus `reasoning_effort` low), no `cache_salt`, a fresh comparison ID per suite, direct LAN
  HTTP.
- **The control carries the overlay.** On its seven-draft single-request steps, arm A
  still broadcasts the unchanged length, a median of 1.2–1.5 ms on rank 0. Its code decode
  (63.7 and 64.3 tok/s) is within cross-load noise of the frozen E31-MB value (63.3 tok/s).
  No instrumentation cost is visible there, but none was measured on the same load either.
- **Excluded diagnostic.** A held-out repeat with reasoning effort low was meant to separate
  the thinking regime from response length. It stopped at its idle check after one request,
  because an external client had started sending requests. It is not used. The screen and
  the suites received no external requests.
- **Counter sampling.** Rank 0 logs its decision counters every 200 participating steps.
  Per-suite counts can therefore shift by up to about 200 steps across a boundary.

## Promotion

The default in `cluster.env.example` produces the measured E35 command on all four ranks,
plus one read-only mount of `policy.flag` (content `hybrid`) at `/tmp/glm53-e35-policy`. In
the measurement window that policy was written into the container at runtime. The operational
identity is `2026-09-30-e35-hybrid`. The one-step return is
`scripts/node/reference/operational-20260930-e31-mb.env`, and overwriting the policy file on
rank 0 with `ema` returns the verify length to the acceptance average without a restart. The
live identity check and the post-boot gates are in the
[promotion record](../../historical_benchmarks/baselines/2026-09-30-e35/promotion.json).
