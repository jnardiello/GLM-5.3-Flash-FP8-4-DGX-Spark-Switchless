# E36: INT8 lm_head shared by the target and the drafter (promoted default)

Promoted on 2026-09-30 by owner decision. `cluster.env.example` selects this directory's runner
and module with `VLLM_E36_LM_HEAD_W8A16=1` and `VLLM_E36_KEEP_BF16=0`, byte for byte the
measured command. `delta.env` is kept unchanged as the record of the measured overlay over the
E35 recipe. The one-step return to E35 is `scripts/node/reference/operational-20260930-e35.env`.
It changes the target's logits slightly, so its fidelity was measured before its speed: dense
perplexity +0.018% against the BF16 head.

The vocab-parallel `lm_head` (38,720 × 4,096 BF16 per rank) is the largest BF16 weight left in
a decode step. The target projects through it once per step, eagerly, and the DFlash2
drafter projects through the same module inside its CUDA graph to pick draft candidates.
Together these took about 2.9 ms of a 60.7 ms C1 step in the E33 profile, limited by
memory bandwidth.

- **`e36_lm_head_w8a16.py`** converts that one module in place: INT8 symmetric, group 128,
  packed for Marlin by the accepted E21 `_pack_projection`, with N padded to 38,912. Every row
  count runs Marlin (no BF16 scratch), so serving and fidelity scoring use the same kernel.
  The BF16 weight is freed (about 155 MB per rank net). The conversion refuses anything but
  an unbiased, unquantized, contiguous BF16 head, and a drafter that does not hold the same
  module.
- **`model_runner.py`** is the promoted E35 runner plus an additions-only wrapper of
  `load_model()`: after the target and the drafter load (and share the head), it converts
  the head once, before any CUDA graph is captured. A failed conversion raises.
- **SparkCache namespace:** unchanged. Logits never feed cached K/V, recurrent state or
  drafter context.

Every rank logs `E36_LM_HEAD_W8A16_READY` with the shape, padded N, bytes freed and added,
whether the drafter shares the module, the group-128 weight error (relative L2), and the
relative L2 and top-1 agreement of eight seeded Gaussian rows through BF16 and INT8.

## Fidelity measurement mode

With `VLLM_E36_KEEP_BF16=1` the BF16 weight stays loaded as well. The flag file named by
`VLLM_E36_FLAG` then selects, for each eager call, the INT8 path (`int8`, the default) or the
BF16 one (`bf16`). It is re-read at most every 0.5 s, and each change is logged as
`E36_LM_HEAD path=...`. One measurement-mode load can therefore score the same corpus with
`bf16` (the current recipe, "Cnow") and with `int8` (the candidate). The drafter keeps the
path active when its graph was captured; it does not affect prompt logprobs. Change the
flag only while the service is idle, write the same value on every rank, and read it back.
The fidelity overlay `scripts/node/experiments/fidelity/le36-m.env` is generated by
`scripts/fidelity/make_overlays.py`.

`scripts/tests/test-e36-lm-head.py` pins the E35 prefix, the additions-only patch, the
manifest and sums, the delta and its refusals, the flag and head checks, and the launcher's
manifest verification.
